# 간편 ELC · 2026-10-25

실행: 이 스튜디오의 `01_START_STUDIO.bat`. 코덱스/API 연결 없이 로컬 코드로 처리합니다.

현재 간편 처리 센서 범위는 기존 엔진과 같은 RedEdge-MX Dual 10밴드입니다. 새 장소에 사용할 수 있지만 다른 센서를 자동 지원한다는 뜻은 아닙니다.

## 사용 순서

1. 01에서 날짜·회차, 원영상·GPS, 실측 타프 반사도 CSV, Ed CSV와 센서 gain을 연결합니다. 새 장소의 타프 ID·실측 반사도는 사용자가 확인합니다.
2. 02에서 모자이크의 타프 위치를 찍고 기준·검증 영상 후보를 선정합니다.
3. 03에서 기준 영상을 선택하고 타프별 중심을 클릭합니다. 자동 사각형을 수정하고, 타프 ID·계수용/검증용·내부 화소 확인을 확정합니다.
4. 왼쪽 `추적`을 실행합니다. 기준 ROI로 후보 전체를 추적하며 다른 영상의 자동 후보는 **미승인**입니다. `검토` 목록에서 항목을 열어 경계·내부 화소를 확인·확정합니다. 검출 실패는 직접 지정하거나 02에서 해당 영상을 제외합니다.
5. `승인 ROI → 04·05 전달` 후 05의 `1. 자동 보정·계수 준비`를 실행합니다. 기본 범위는 선정한 기준·검증 영상만입니다. GPS 전체 처리는 별도 체크합니다. 중간 radiance 저장 여부는 04의 기존 옵션을 따릅니다.
6. 촬영시간 추출·실측 Ed 매칭·용량 검사·방사보정·파장별 센서 교정·Ed 정규화·계수 산출까지 자동 진행합니다. 계수 준비 완료에서 멈춥니다.
7. 열린 보고서에서 기준과 계수를 확인한 뒤 `2. 계수 확인·반사도 생성`을 실행합니다. 독립 검증과 반사도 생성이 진행되며, 전체 범위를 선택했다면 나머지 영상도 생성합니다.
8. `품질 보고서`에서 대역별 독립 검증 RMSE(pp)·Bias(pp)·rRMSE(%), 계수 적합, 승인 ROI 이미지, Ed 시각·파장별 비율 CSV를 확인합니다. 중간 radiance가 없으면 기존 보정 전후 비교가 생략될 수 있습니다. `결과 폴더`로 TIFF와 설정 파일을 바로 엽니다.

## 자동화와 승인 경계

- 기준 타프를 이름·반사도와 연결하는 최초 지정은 사람의 역할입니다. 새로운 장소를 좌표 JSON 하나로 자동 식별하지 않습니다.
- 영상 간 추적은 기존 native SIFT/RANSAC 정합과 클릭 중심 기반 사각형 검출을 조합합니다. 왕복 정합 2 px, 예측-검출 사각형 IoU 0.5는 **검토 후보를 만들기 위한 공학적 필터**이며 정확도 보증이나 승인 기준이 아닙니다. 자동 생성 결과는 모두 확인해야 합니다.
- 기준 영상의 그림자 제외 브러시와 승인을 다른 영상으로 복사하지 않습니다. 영상별로 다시 확인합니다.
- 전체 추적을 다시 해도 이미 확정한 대상 ROI는 유지합니다. 출처 영상·변환행렬·왕복 오차·경계 중첩률을 기록합니다.
- 밴드 간 ROI 전달과 영상 간 추적은 다릅니다. 승인 전달 시 해당 촬영분의 native B6 ROI를 밴드별 좌표로 변환합니다. Photos·모자이크 좌표를 원영상에 직접 적용하지 않습니다.
- 계수 산출은 승인 기준 영상의 계수용 타프만 사용합니다. 다른 영상과 검증용 타프는 독립 검증에 사용하며 계수에 넣지 않습니다.
- 계수 산출 후 별도 사용자 확인 없이는 반사도를 생성하지 않습니다. 설정·ROI·계수·보정 자료가 변경되면 이전 승인을 재사용하지 않습니다.
- 완료는 계산과 파일 검사의 완료입니다. 독립 검증 오차를 확인하지 않고 품질 합격으로 해석하면 안 됩니다. 임의의 보편적 합격 임계값을 추가하지 않았습니다.

## 저장과 자원

- 회차 폴더에 `Easy_ELC_날짜_시각_UUID/`를 새로 생성합니다. 원영상과 기존 5·6회차 결과를 덮어쓰거나 삭제하지 않습니다.
- 정규화 Float32 TIFF와 반사도 Float32 TIFF를 유지합니다. 선택 시 센서 교정 radiance가 추가됩니다. 사진 크기에 따른 비압축 예상량과 20% 여유를 실행 전에 검사합니다.
- `project.json`, `easy_status.json`, `quality_report.html`, `Coefficients/`, `Reflectance/`, `Integrated/`에 실행 설정·계수·보고서·Ed/시간/파장 근거를 보존합니다.
- 원래 프로젝트 옆 `.easy-elc.json`은 최신 실행을 가리키는 포인터입니다. 원래 프로젝트 입력·계수 경로는 자동으로 바꾸지 않습니다.
- 앱을 켜 둔 상태에서 실행합니다. 기존 중지 버튼은 해당 실행의 자식 프로세스까지 중지합니다. 앱 재시작 후 승인 대기 결과를 이어갈 수 있지만, 중단된 대량 처리의 자동 재개는 이번 범위에 포함하지 않았습니다.
- 기존 보정 결과를 임의로 믿고 재사용하지 않습니다. 이 간편 경로는 새 통합 보정 결과를 생성하므로 이미 완료한 회차에 다시 실행하면 추가 용량과 시간이 필요합니다.
- ExifTool 실행 검사에 실패하면 대량 보정 전에 중단하고 오류를 보고서에 기록합니다. 이 환경의 기존 통합 회귀 검사에서는 Windows DLL 실행 오류(WinError 623)가 발생했으므로 실제 DN→반사도 전체 연결을 새로 통과했다고 주장하지 않습니다.
