# GENERAL 사용 안내

GPS 없는 native ELC 5단계로 반사도 영상 산출까지만 진행합니다. 최종 제공 범위는 native 밴드별 ELC TIFF, 10밴드 계수 CSV, ROI·타프 독립 검증 HTML입니다. 실제 검사 사실은 [검증 기록](../VALIDATION.md)을 참조합니다.

## 1. 자료 연결

1. 실제 날짜·세션·현장을 확인하고 해당 `project.json`을 엽니다. 외부 입력은 결과 폴더 밖에서 직접 선택합니다. 원본을 이동하지 않습니다.
2. EXIF/XMP가 보존된 native UInt16 MX Dual Raw를 전체 재귀 스캔합니다. 평면·임의 하위 폴더를 허용합니다. 중복 촬영번호/밴드, 부분·빈 밴드는 원인을 해결하며 조용히 제외하지 않습니다.
3. `shot` CSV로 retained-shot 대상을 명시적으로 등록합니다. 스캔 성공은 전체 처리 동의가 아닙니다. 타프 실측값·gain·Ed는 본인 자료를 연결합니다.

## 2. 원영상 후보

1. 등록 대상에서 실제 타프가 있는 native 원본을 확인합니다. 미리보기는 필요한 영상만 지연 로딩하고 크기를 제한하며, 미리보기를 반사도 계산 입력으로 쓰지 않습니다.
2. 기준 영상과 별도 독립 검증 영상을 골라 후보 부분집합을 저장합니다. 최소 2촬영, 밴드마다 서로 다른 반사도의 유효 타프 최소 2개가 필요합니다.
3. 후보는 native 원본에서 선택합니다. 지도·모자이크 기반 후보 탐색이나 별도 공간 분석 메뉴를 사용하지 않습니다.

## 3. 타프 ROI·승인

1. 최신 ROI 편집기에서 타프 경계·내부 영역을 조정하고 추적 결과를 영상별로 확인합니다. 자동 추적·정합은 제안이지 승인이 아닙니다.
2. ROI 경계, 공간 trim, 그림자/이상 화소 제외, P05~P95 값 필터, 포화를 따로 검토합니다. 빈 제외 마스크가 포화 해제를 뜻하지 않습니다.
3. 기준 적합용과 검증용 역할을 구분하여 ROI를 승인합니다. 타프 실측값의 ID와 ROI ID도 일치시킵니다.
4. 정합은 ROI를 각 밴드의 원본 좌표로 전달하기 위한 것입니다. 통계와 최종 영상은 native 밴드 격자를 유지하며, 정합된 영상으로 전체 Raw를 대체하지 않습니다.

## 4. 방사·센서·Ed

1. 실제 EXIF 시각으로 원본 시간대 UTC/KST(`Asia/Seoul`)를 확인합니다. Ed CSV의 `datetime_kst`와 시간대·단위를 맞춥니다. 임의 시간 보정으로 매칭을 만들지 않습니다.
2. 방사보정 → 실제 파장별 sensor gain 한 번 → 실측 Ed 정규화 순서를 유지합니다. 뒤 단계에서 gain을 다시 적용하지 않습니다.
3. 기준·대상 모두 최근접 실측 Ed를 5초 이하로 매칭합니다. 보간·평균·외삽하지 않으며, 실측 범위 밖·시간차 초과는 차단 원인입니다.
4. GPS는 실제 좌표를 이용한 태양각 기록용 선택 입력입니다. 없어도 촬영시각·Ed 정규화를 사용하며, 내부 `image_time_solar.csv`의 태양각은 빈 값/`unavailable`로 둡니다. 가짜 GPS·태양각을 채우지 않습니다.
5. 메타데이터 경로 사전 검사에서 차단되면 새 전용 환경의 ExifTool 13.07 이상을 사용하거나 루트를 짧게 지정합니다. 한글 경로 복사는 UTF-8 인자 파일과 제한시간을 사용합니다. [경로 제한](KNOWN_LIMITS.md)을 우회하지 않습니다.

계산 기준은 `L_norm = L_rad × gain × Ed(t0)/Ed(t)`입니다. `t0`는 승인한 기준 촬영이며, 타프 계수는 같은 보정 기준에서 `L_norm = a*rho + b`로 구합니다.

## 5. ELC 계수·반사도

1. 후보 우선 범위와 디스크 여유를 확인한 뒤 `1. 자동 보정·계수 준비`를 실행합니다. 이 실행은 촬영시간·방사·센서·Ed와 계수 산출을 연결합니다.
2. `awaiting_review`에서 멈추면 `quality_report.html`을 엽니다. 기준 영상, 실제 파장별 10개 a·b, ROI·포화·적합 범위·보정 출처를 확인합니다. 아직 반사도 생성 완료가 아닙니다.
3. `2. 계수 확인·반사도 생성`에서 사용자 적용 승인을 별도로 수행해야 finish가 진행됩니다. `rho = (L_norm - b)/a`로 native 밴드별 Float32 ELC TIFF를 만들고 ROI·타프 독립 검증 HTML을 확인합니다.
4. 기준 적합 잔차를 독립 정확도로 부르지 않습니다. 다른 촬영의 검증값과 기준 영상에서 보류한 검증 ROI도 구분합니다. 보고서의 Bias/RMSE는 pp, 상대 RMSE는 %이며 유효 화소 수·타프/촬영 수·Ed 시간차를 함께 봅니다.
5. 후보 시험을 검토한 뒤에만 **전체 등록 대상 처리**를 선택합니다. 01의 `선택 ELC 영상만 처리`를 해제하고 05의 `등록된 전체 촬영분 생성`을 명시적으로 선택한 뒤 새 준비·검토·승인을 거칩니다. Raw 폴더의 모든 파일이나 GPS 목록 전체를 자동 처리하는 뜻이 아닙니다.

원본·대상 CSV·후보·기준·시간대·gain·Ed·타프·ROI·계수가 바뀌면 해당 서명과 승인을 무효화하고 필요한 단계부터 다시 검토합니다. 승인 플래그·해시를 직접 고쳐 재개하지 않습니다. `complete`는 처리 완료이지 과학적 합격 판정이 아닙니다. 음수 또는 1 초과 반사도를 잘라 숨기지 않습니다.

## 결과와 보고서 찾기

생성 결과는 `general.project_root` 아래입니다. 표의 키는 `preparation.locations()`의 경로 계약입니다. 세부 폴더를 추정하지 말고 현재 실행 설정·`plan.json`·상태 파일·보고서 링크를 따라갑니다.

| 경로 키/실행 위치 | 내용 |
|---|---|
| `base`, `configs` | 기본 처리 루트와 단계별 생성 설정·대상 목록 |
| `qc`, `rad`, `ed` | 품질 기록, 선택 저장 방사 결과, gain·Ed 보정 결과 |
| `coef`, `ref` | 10밴드 `elc_coefficients.csv`, 통계·보고서, 밴드별 Float32 반사도 |
| `roi` | 프로젝트의 영구 ROI·선정·승인 기록. 간편 실행이 바뀌어도 실행 폴더로 이동시키지 않음 |
| `Easy_ELC_*` | 프로젝트 루트의 직접 하위에 격리한 실행. `project.json` 사본·`easy_status.json`·`quality_report.html` 보관 |

통합 실행 결과가 연결되면 `ed`는 그 실행의 `Ed_Normalized`를 가리킬 수 있습니다. 중간 radiance 캐시를 끄더라도 최종 정규화 영상·반사도·기록은 구분하여 보존합니다.

| 최종 산출물/검토 HTML | 읽는 목적 |
|---|---|
| `ref`의 밴드별 Float32 ELC TIFF | native 크기·밴드별 원본 격자를 보존한 반사도 영상 |
| `elc_coefficients.csv` | 실제 파장별 10밴드 a·b와 기준 정보 |
| `quality_report.html` | 승인 ROI 확인·계수·독립 검증 HTML의 실제 링크 |
| `elc_coefficient_validation.html` | 기준 타프 적합 검토. 독립 정확도와 구분 |
| `elc_priority_reference_validation.html` | 다른 촬영·타프의 독립 검증과 ROI 역할별 수치 |

설정·촬영시각·중간 보정·상태 파일은 재현과 점검을 위한 내부 기록입니다. 별도 공간 분석 산출물을 제공한다는 뜻이 아닙니다.

생성된 보고서의 실제 링크만 사용합니다. 없는 파일을 완료로 간주하거나 고정 경로에 결과를 복사해 맞추지 않습니다.

## 보존·중지와 외부 후속 작업

1. 처리 중에는 작업창을 닫지 않습니다. 중지·실패 후 상태·로그·디스크와 실행 프로세스를 확인합니다. 원본·실측 자료·ROI·계수·보고서를 보존하고 기존 결과를 묵시적으로 덮어쓰지 않습니다.
2. 이 패키지는 native ELC 산출에서 끝납니다. 사용자가 나중에 외부 Metashape 프로젝트의 영상 경로를 산출 TIFF로 재연결할 수는 있으나, 정사화·모자이크 생성과 해당 소프트웨어·라이선스는 패키지 범위 밖입니다.

## 버튼이 작동하지 않거나 오류가 날 때

1. 처리·후보·등록 버튼 위에 커서를 잠시 두면 동작 설명 또는 현재 막힌 이유가 표시됩니다. 비활성 버튼도 클릭하면 이유를 볼 수 있습니다. 키보드로 선택한 버튼의 `F1`도 안내를 엽니다.
2. 하단 `진행이 안 되는 이유`는 현재 단계의 각 작업별 미연결 자료·선행 작업·현재 처리 상태를 한 번에 설명합니다. 안내 확인은 설정·승인·처리를 변경하지 않습니다.
3. 원영상 스캔 실패, 설정 저장 오류와 실제 처리 실패는 원문 오류·확인할 조치·관련 위치를 안내합니다. 처리 실패의 전체 traceback은 회차 설정 옆 `Logs/failure_*.log`에 보존하고 팝업에는 해당 경로를 표시합니다.
4. 안내는 입력 연결 상태와 알려진 오류 문구를 기반으로 합니다. 내용·파장·승인 서명·Ed·용량의 최종 검사는 원래 처리기에서 수행합니다. 원인 미확정 오류는 단정하지 않으며 자동 재시도·자료 대체·승인 우회를 하지 않습니다.
5. 툴팁은 현재 폼과 파일 연결 상태만 확인합니다. 원영상 화소 읽기·전체 폴더 스캔·방사보정이나 네트워크 전송을 하지 않습니다. `다음 단계`는 화면 이동이며 처리 완료·검증 통과를 뜻하지 않습니다.
